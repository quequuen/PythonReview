## 1. 클래스 설계

본 프로그램은 최소 다음 2개의 클래스를 구현해야 한다.

---

### 1) Animal 클래스

Animal 클래스는 **동물 1마리의 기본 정보와 예방접종 기록 목록**을 관리한다.

다음 속성을 포함해야 한다.

- `animal_id` (동물 고유 ID)
- `species` (동물 종류/종)
- `name` (동물 이름)
- `birthdate` (출생일, 날짜 객체로 관리)
- `owner_name` (보호자 이름)
- `records` (예방접종 기록 리스트)

Animal 클래스는 다음 기능을 수행하는 메서드를 포함해야 한다.

1. `get_age_days()`
    - 오늘 날짜를 기준으로
        
        해당 동물의 생후 일수를 계산하여 반환한다.
        
2. `get_age_weeks()`
    - 오늘 날짜를 기준으로
        
        해당 동물의 생후 주차를 계산하여 반환한다.
        
3. `add_record(record)`
    - 예방접종 기록을 추가한다.
    - 단, **같은 예방접종 이름이 이미 기록되어 있고
    출차 미완료 같은 개념으로 “동일 예방접종의 중복 등록이 금지”라는 조건이 주어질 수 있으므로**,
    본 메서드는 내부에서 중복 여부를 검사한 뒤
    등록 성공 시 `True`, 실패 시 `False`를 반환하도록 구현한다.
4. `remove_record(vaccine_name, shot_date)`
    - 예방접종 이름과 접종 날짜가 동시에 일치하는 기록 1건을 찾아 삭제한다.
    - 삭제 성공 시 `True`, 실패 시 `False`를 반환한다.
5. `get_due_records(base_date=None)`
    - 다음 예방접종 예정일 기준으로
        
        **기한이 도래했거나 지나버린 기록**만 골라 리스트로 반환한다.
        
    - `base_date`가 주어지지 않으면
        
        **오늘 날짜를 기준으로 판단**한다.
        

---

### 2) VaccineRecord 클래스

VaccineRecord 클래스는 **예방접종 1건**을 표현한다.

다음 속성을 포함해야 한다.

- `vaccine_name` (예방접종 이름)
- `shot_date` (접종일, 날짜/시간 객체로 관리)
- `next_due_date` (다음 예방접종 예정일, 없을 수도 있음)

VaccineRecord 클래스는 다음 기능을 수행하는 메서드를 포함해야 한다.

1. `is_due(base_date=None)`
    - 다음 예방접종 예정일이 존재하는 경우
        
        기준 날짜(없으면 오늘 기준)와 비교하여
        
        기한 도래 여부를 `True/False`로 반환한다.
        
    - 다음 예방접종 예정일이 존재하지 않으면
        
        기한 판단 대상이 아니므로 `False`를 반환한다.
        
2. `__str__()`
    - 예방접종 기록을 사람이 읽기 좋은 형태로 출력하기 위한
        
        문자열 표현을 정의한다.
        

---

## 2. 파일 저장/복구 설계

동물별 예방접종 기록은 **동물 ID 단위로 파일에 저장**해야 한다.

- 저장 폴더 예시: `c:\animal_vaccine_학번`
- 파일명 예시: `{animal_id}.txt`

파일은 “동물 1마리의 예방접종 기록 목록”을 저장하는 용도이며,

프로그램은 다음 기능을 반드시 구현해야 한다.

1. **기록 복구 기능**
    - 사용자가 동물 ID를 입력했을 때
        
        해당 ID의 기록 파일이 존재하면
        
        파일에 저장된 예방접종 기록을 읽어
        
        `Animal.records`에 복구한다.
        
    - 복구 후
        
        해당 동물의 기록 요약을 출력한다.
        
2. **기록 저장 기능**
    - 예방접종 기록이 추가 또는 삭제되면
        
        변경된 `Animal.records`를
        
        해당 동물의 파일에 다시 저장한다.

## 3. 프로그램 실행 흐름

프로그램은 다음 순서를 따른다.

1. 프로그램 시작 시
    
    지정 폴더가 존재하지 않으면 폴더를 생성한다.
    
2. 사용자는 반복적으로
    
    동물 ID를 입력할 수 있어야 한다.
    
    - 동물 ID를 입력하지 않고 Enter를 누르면
        
        프로그램을 종료한다.
        
3. 입력된 동물 ID에 대해
    - 해당 ID의 Animal 객체가 메모리에 없다면 새로 생성한다.
    - 기록 파일이 존재하면
        
        예방접종 기록을 복구하여 출력한다.
        
4. 해당 동물에 대해
    
    사용자 메뉴를 통해 다음 작업을 수행할 수 있어야 한다.
    
    (1) 동물 기본 정보 입력/확인
    
    - 동물 종류, 이름, 출생일, 보호자 이름을 입력/확인한다.
    - 출생일은 문자열 입력을 받아
        
        날짜 객체로 변환해 저장한다.
        
    
    (2) 예방접종 기록 추가
    
    - 예방접종 이름, 접종일을 입력받아 기록을 생성한다.
    - 다음 예방접종 예정일 입력이 있을 경우 저장한다.
    - 다음 예방접종 예정일 입력이 없으면
        
        해당 값은 “없음 상태”로 저장한다.
        
    - 중복 조건에 의해 등록이 실패할 수 있으며
        
        실패 시 적절한 안내 문구를 출력한다.
        
    
    (3) 예방접종 기록 삭제
    
    - 예방접종 이름과 접종일을 입력받아
        
        일치하는 기록을 삭제한다.
        
    
    (4) 기한 도래 기록 조회
    
    - 기준 날짜를 입력받아 조회할 수도 있고
        
        입력이 없으면 오늘 기준으로 조회한다.
        
    - 기한 도래 기록 목록을 출력한다.
    
    (5) 동물 나이 정보 출력
    
    - 오늘 기준 생후 일수와 주차를 출력한다.
5. 기록이 변경되는 모든 기능 수행 후에는
    
    해당 동물의 기록 파일을 즉시 갱신 저장한다.
    

---

## 4. 출력 요구

다음 정보가 적절히 출력되어야 한다.

1. 동물 기본 정보
    - 동물 ID, 종류, 이름, 보호자, 출생일
2. 나이 정보
    - 생후 일수
    - 생후 주차
3. 예방접종 기록 목록
    - 예방접종 이름
    - 접종일
    - 다음 예방접종 예정일(있는 경우)
    - 기한 도래 여부가 구분 가능하도록 출력

---

## 5. 구현 조건

- 반드시 **클래스 기반 구조**로 작성한다.
- 예방접종 기록은 반드시 **객체 리스트로 관리**한다.
- 저장/복구 기능은 반드시 포함한다.
- 데이터가 없는 경우에도
    
    프로그램이 정상적으로 동작하도록 처리한다.
